# seam — 分布式分块色调映射的接缝分析

一帧被水平切成 P 块、分到 P 个 worker 各自做色调映射（tonemap），拼接后交界出现一条
颜色偏深的横线。本模块给出两种成因的处理表达式、差异量的闭式解、由量化预算反解的
统计量一致性范围，以及 P = 2 / 4 / 8 三档实测。

`make test` 跑自检与三档实验；`./seam <csv>` 额外写 CSV。产物在 `../artifacts/seam/`
（运行日志、CSV、双曲线 HTML）。

## 1. 交界处的处理表达式

色调映射采用与本仓库 `tonemap/` 一致的 Reinhard 曲线，锚点 s 取统计窗口的
对数平均亮度 Lw（key=1）：

```
T(x; s) = x / (s + x),   s = Lw = exp( mean( log(x + eps) ) )
```

交界行有两种故障机制。

### 机制 A：交界像素被两边各映射一次（重复映射）

worker 已对该行做过一次 `T(x; s_g)`，合成/拼接阶段又把它当作普通 LDR 像素
过了一遍曲线（第二次的"输入"已是 [0,1)，等价于锚点 s=1 的 Reinhard）：

```
T2(x) = T( T(x; s_g); 1 )
      = [ x / (s_g + x) ] / [ 1 + x / (s_g + x) ]
      = x / (s_g + 2x)
```

令归一化亮度 u = x / s_g，则一次映射 `T1 = u/(1+u)`，两次映射 `T2 = u/(1+2u)`。
曲线严格凹，复合后该行**只可能变暗**，这正是"横线颜色比两边略深"。

### 机制 B：两边各自统计，锚点不同（统计不一致）

上侧块统计量 s_a、下侧块统计量 s_b，同一辐射度 x 在交界两侧被映成两个值：

```
T(x; s_a) = x / (s_a + x),   T(x; s_b) = x / (s_b + x)
```

每个 worker 内部曲线连续，所以故障表现为**交界行处的一步跳变**，而不是整行变暗。

## 2. 两种情形的差异量

### 机制 B 的差异量（精确闭式）

```
ΔT_stat = | T(x;s_b) − T(x;s_a) |
        = x |s_b − s_a| / [ (s_a + x)(s_b + x) ]
```

定义锚点相对差 ρ = |s_b − s_a| / s，其中 s = (s_a+s_b)/2，并令 s_b > s_a，
s_a = s(1−ρ/2)，s_b = s(1+ρ/2)，u = x/s，g(u) = u/(1+u)²：

```
ΔT_stat(u; ρ) = ρ · u / [ (1+u)² − (ρu/2)² ]
```

对 u 求导取最坏点（一阶条件解出 u* = √(1−ρ²/4)），得精确上界：

```
ΔT_stat,max(ρ) = ρ / [ 2 ( 1 + √(1 − ρ²/4) ) ]
```

ρ 很小时 √(·) ≈ 1，退化为一阶界 `ΔT ≤ ρ/4`（g(u) 在 u=1 处取峰值 1/4）。
ρ 较大（本实验有 ρ > 100% 的情形）时一阶界失效，必须用精确式——代码里的
`bound_rho_exact` 自检覆盖全部实测接缝，`bound_rho_first_order_limit` 只在 ρ<5% 时
检验一阶近似。

### 机制 A 的差异量（重复映射的暗化量）

```
ΔT_dbl = T1 − T2 = u/(1+u) − u/(1+2u)
       = u² / [ (1+u)(1+2u) ]
```

小 u 时 ΔT_dbl ≈ u²：暗区（u≪1）重复映射几乎无损；u=1 时暗化 1/6 ≈ 0.167 LDR
（约 42 个量化级），亮区趋近 1/2。它是**偏差**（恒暗、与分块统计无关，全局锚点也救不了），
机制 B 是**跳变**（两侧一亮一暗、差的符号随锚点大小翻转）。两种机制的修复方式因此不同：
A 要在管线里保证每像素只过一次曲线（明确 overlap 行归属），B 要统一统计量。

## 3. 由"差不超过一个量化级"反解统计量一致性范围

8-bit 输出，一个量化级 q = 1/255 LDR。要求 ΔT_stat,max ≤ q，代入精确上界反解 ρ：

```
ρ* = 4q / (4q² + 1) = 1.5685%          （一阶近似即 4/255 = 1.5686%，几乎无差）
```

换算回统计量本身。s_a/s_b = (1−ρ/2)/(1+ρ/2)，故两侧对数平均亮度必须满足：

```
| ln s_b − ln s_a | ≤ artanh(ρ/2) = 0.0078
⇒ 两侧 Lw 相差不超过约 ±0.78%（比值落在 [0.9845, 1.0158] 内）
```

这是**必要且充分**的最坏情形界（在 u* 处取等）。注意它只约束统计量，不约束画面内容：
内容梯度本身在全局映射下是连续的，制造接缝的只有锚点差。

机制 A 没有统计量可调：把 ΔT_dbl ≤ q 按 u 反解，得到 u ≲ √q ≈ 0.063，即只有极暗像素
能容忍双映射；常规亮度区间全部超标，只能靠消除重复处理本身解决。

## 4. 方案取舍：两条曲线

| 方案 | 接缝质量 | 每帧额外开销 |
|---|---|---|
| 局部统计（零通信） | 锚点随块内容漂移，ρ 实测 9.6%–108%，接缝 6–75 cv，全部 FAIL | 0 |
| 全局统计（先归约） | 所有 worker 共用 s_g，ρ ≡ 0，三档接缝恒为 0 cv，PASS | 树形 all-reduce ⌈log₂P⌉ 轮延迟、2(P−1) 条消息 |
| 重复映射（管线 bug） | 交界行暗化 32–106 cv，与 P 无关，全部 FAIL | 无省到通信，纯故障 |

两条曲线（见 `seam_curves.html`）：

- 质量曲线：局部统计的接缝跳变随 P 单调恶化（19.8 → 30.3 → 75.2 cv），因为块越小
  统计窗口越窄、块间内容差异越大；全局统计是贴 0 的水平线；预算线在 1 cv。
- 开销曲线：归约轮数 1 → 2 → 3（对数增长，P 翻倍只多一轮），消息数 2 → 6 → 14。

结论：在本预算（1 cv）下局部统计没有可行域——实测最小 ρ=9.57% 仍是阈值 1.57% 的
6 倍以上，归约无法回避。推荐**全局对数平均 + 单遍映射**：归约代价仅 ⌈log₂P⌉ 轮且
只传输标量（每机一个 log-sum），通信量与像素数无关；若要进一步压缩延迟，折中是
分块组内归约 + 交界 feather 混合，但只要混合窗口两侧锚点差超过 ρ* 就不达标，需要按
第 3 节的界在线校验。
