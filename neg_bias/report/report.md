# 色调映射前三步减法的负值分析与偏置取舍

## 0. 数据来源与可复现性

仓库未包含锐化、色差模块，也未附带真实像素 dump（`artifacts/` 仅有 `workspace.json`）。
为使结论可测量、可复现，在 `neg_bias/` 下用纯 C 搭建确定性脚手架，合成三档 1920×1080
（N=2,073,600）HDR 场景作为 dump 的替代输入：

| 档位 | 基础辐射度 | 种子 | Lmin | Lmax | 通道最大值 |
|---|---|---|---|---|---|
| 暗 | 0.05 | 101 | 0.000470 | 4.280841 | 4.445412 |
| 中 | 0.35 | 202 | 0.003264 | 25.735554 | 27.286379 |
| 亮 | 1.50 | 303 | 0.014609 | 115.930000 | 119.736206 |

场景由低频基座 + 对数正态噪声（σ=0.28，保均值）+ 0.8% 暗斑（×0.05）+ 1.2% 高光
（×4~40）构成；R/B 通道在强横向梯度处做 1px 错位并加 4% 增益噪声，模拟串色与色散条纹。
所有数字由 `make run` 重新生成，图表数据由 `python3 -I tools/gen_data.py` 从输出 CSV 生成，
无手抄环节。换成真实 dump 时只需替换输入数组，分析代码不变。

常量：高光阈值 T=1.0；锐化盒式模糊半径 r=1（与 `bloom/src/bloom.c` 的 `box_blur` 同构）；
复合权重 bloom 0.3、unsharp 0.5、CA 0.5；色调映射取 Reinhard `x/(1+x)`；
达标线 1/10000（对应每帧 ≤207 个像素）；半量化级预算 1/512≈0.001953（LDR 8bit 量化级 1/255 的一半）。

## 1. 哪三步产生负值——各自的取值下界

三步都是「无界减法」，输入本身非负不代表差非负。设帧内辐射度最小值 Lmin、最大值 Lmax。

### 1.1 高光提取（bright-pass）：d₁ = L − T

- 差的下界 = **Lmin − T**（本场景 T=1.0，即 Lmin − 1.0，三档分别约 −0.9995、−0.9967、−0.9854）；
  通用硬下界为 **−T**（Lmin≥0 时）。
- 上界 = Lmax − T。
- 实测最小负值：暗 −0.999530、中 −0.996736、亮 −0.985391，与 Lmin−T 完全吻合。
- 这是设计上的「半波整流」：`bloom.c` 里 `dst = v>0 ? v : 0`，负支本来就该被丢弃，
  不携带暗部信息——它产生负值是预期行为，不是 bug。

### 1.2 锐化（unsharp mask）：d₂ = c − blur(c)

半径 r 的盒式均值是邻域的凸组合（权重和为 1、系数非负），故 blur(c)∈[Lmin, Lmax]。

- 下界 = **Lmin − Lmax = −(Lmax−Lmin)**（中心取到最暗、邻域均值取到最亮时达到）；
- 上界 = Lmax − Lmin，关于零对称；平坦场恒为 0。
- 实测最小负值：暗 −0.597078、中 −4.096127、亮 −15.814035，均在 [Lmin−Lmax, …] 之内
 （对应解析界 −4.2804、−25.7323、−115.9154）。
- 负支是**有意义的信号**：它表示「中心比邻域暗」的边缘（暗侧振铃），钳零等于只保留亮侧边缘。

### 1.3 色差（chromatic aberration）：d₃ = R − B

两通道各自非负、互相独立。

- 下界 = **−Bmax**（R=0 而 B 取帧内最大值时达到）；上界 = Rmax；本场景 Bmax 即通道最大值，
  解析界三档为 −4.4454、−27.2864、−119.7362。
- 实测最小负值：暗 −3.955122、中 −24.692829、亮 −114.013229，落在界内。
- 负支同样是信号：负号编码条纹方向（蓝边在右还是在左），钳零丢失方向信息。

## 2. 钳到零的后果：信息损失量 = |负值|，且色调映射不可恢复

对任一步减法输出执行 `max(d,0)`：

- d≥0 时不变；d<0 时输出 0，损失的差分量恰为 **0 − d = |d|**；
- 该钳制发生在色调映射**之前**，之后 Reinhard/ACES 只看到 0。任何单调色调映射曲线都无法
  从 0 还原出原负值——信息在进入曲线前已被销毁，损失量（减法域）就是原负值的绝对值。

端到端实测（有符号直通、仅在显示端钳一次，对比逐减法钳零；输出为 Reinhard 后的 LDR 帧）：

| 档位 | 两管线 RMSE | 有符号管线在色调映射前仍为负的像素 | 被显示钳削掉的 HDR 能量/像素 |
|---|---|---|---|
| 暗 | 0.011381 | 127,517（6.15%） | 0.006071 |
| 中 | 0.059438 | 126,523（6.10%） | 0.041943 |
| 亮 | 0.138733 | 123,456（5.95%） | 0.177571 |

误差随场景亮度放大：亮档每像素被削能量 0.178 HDR 单位，折算到 LDR 已远超一个量化级。
另注意一个实现陷阱：Reinhard `x/(1+x)` 对 x<−1 会翻号（x→−∞ 时趋于 −1），所以显示钳制
必须作用在曲线**输入**上；本仓库 `tonemap.c` 的 ACES 是在输出端钳，对负输入同样不安全。

## 3. 由「负值占比 ≤ 1/10000」反解每步最小偏置 b*

在减法**之前**加偏置：d' = d + b，再对 d' 钳零。把减法输出的负值按从小到大排序
（最负在前），令 K = ⌊N/10000⌋ = 207。要使残余负值数 ≤ K，偏置必须覆盖到第 K+1 负的值：

**b\* = −d₍K+1₎**（第 208 个最负像素的绝对值；等号使该像素恰好落到 0，不计负值）。

b<b\* 时残余负值 >207 即不达标；b=b\* 是满足占比约束的最小偏置。实测：

| 档位 | 步骤 | 负值像素数（占比） | 最小负值 | b\*（达标最小偏置） |
|---|---|---|---|---|
| 暗 | 高光提取 | 2,065,557（99.61%） | −0.999530 | **0.999159** |
| 暗 | 锐化 | 1,189,417（57.36%） | −0.597078 | **0.381970** |
| 暗 | 色差 | 1,037,280（50.02%） | −3.955122 | **2.316458** |
| 中 | 高光提取 | 2,049,263（98.83%） | −0.996736 | **0.994133** |
| 中 | 锐化 | 1,188,811（57.33%） | −4.096127 | **2.654499** |
| 中 | 色差 | 1,036,001（49.96%） | −24.692829 | **16.189100** |
| 亮 | 高光提取 | 862,794（41.61%） | −0.985391 | **0.974574** |
| 亮 | 锐化 | 1,188,690（57.32%） | −15.814035 | **11.462338** |
| 亮 | 色差 | 1,036,896（50.00%） | −114.013229 | **69.597343** |

## 4. 取舍：负值占比曲线 vs 亮度抬升曲线

偏置对所有被钳零的像素注入 `g·b` 的辐射度（g 为该步复合权重），经 Reinhard 后形成整帧
平均亮度抬升 lift(b)。两条曲线都随 b 单调：负值占比下降、抬升上升。在每个档位面板里
（`report/bias_curves.html`），红色达标线 1e-4 与占比曲线的交点横坐标是 b\*，紫色预算线
1/512 与抬升曲线的交点横坐标是预算允许的最大偏置 b_b；**b\* ≤ b_b 才有可行解**。

实测结论：**九种组合全部不可行（pass=0）**。b\* 处的实际抬升与预算耗尽时的残余负值：

| 暗 | 高光提取 | 0.010496 | 否（超 5.4×） | 0.962883 | 1,122,853（54.15%） |
| 暗 | 锐化 | 0.144095 | 否（超 73.8×） | 0.007609 | 600,375（28.95%） |

### 超预算档位按要求给出的三项数据

- **该档负值像素数与最小负值**：见第 3 节表（九组全部超标，无一豁免）；
- **每步建议偏置量**：占比达标所需的最小偏置即 b\* 列；若反过来守住半量化级预算，
  可用偏置上限即 b_b 列（此时占比不达标，残余负值数见末列）；
- 两列之间不存在交集，这正是两条曲线给出的取舍结论，而不是参数没调好。

## 5. 结论与建议

1. **偏置方案在本约束下无解。** 根因是负值不是稀有尾事件：锐化与色差的负值占比天然在
   50%/57% 量级（零均值差分的两侧），高光提取在暗档达 99.6%。要把 50% 压到 0.01%，偏置必须
   接近差分分布的主体尺度，整帧抬升必然超过半个量化级两到三个数量级。
2. **正确修法是保留有符号中间值，只在显示端钳一次。** HDR 中间缓冲用有符号浮点（或定点），
   减法结果直通复合与色调映射；把 `max(·,0)` 移到色调映射曲线的输入侧。端到端对照显示
   这样做消除了两管线间 0.011~0.139 的 RMSE，且不引入任何亮度抬升。
3. **高光提取是唯一的例外。** 它的负支本就是设计丢弃项（半波整流），保持现状钳零即可，
   不需要偏置；需要关注的只有锐化与色差两步。
4. **若硬件只能存无符号值**，退而求其次的顺序是：先按 b_b 给偏置（守住半量化级预算），
   再如实上报残余负值占比（本表末列，14%~79%），而不是为了占比指标牺牲亮度预算；
   同时应在显示端而非各减法端钳制，并修正 `tonemap.c` ACES/Reinhard 对负输入的钳制位置。
5. 量化级预算应以**实现的色调映射后抬升**为准（本脚手架的口径），不能用减法域的 g·b/N
   直接折算——Reinhard 在亮区压缩、暗区增益，两种口径在亮档可相差数倍。

## 6. 复现方式

```
cd neg_bias
make run                       # 生成 out/results.txt 与 9 条扫描曲线 CSV
python3 -I tools/gen_data.py   # 生成 report/data.js
# 浏览器打开 report/bias_curves.html（支持 ?theme=dark、十字线 tooltip、数据表格）
node tools/smoke_chart.cjs "$PWD/report"   # 交互冒烟（需 playwright）
```
