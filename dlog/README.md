# dlog

把 `tonemap → bloom → dof → present` 串起来跑，把每步的输入域/输出域写进
运行日志，事后只凭日志判定有没有步骤被重复执行。

`make test` 跑三档各一次：正常参照（每步一次）+ 事故复现（T、D 各两次）。

## 判据

| 量 | 定义 |
|---|---|
| 输入域 D_m | 该步声明能接受的码值区间，`[0,1]` 码值单位 |
| 输出域 R_m | 该步声明的输出区间 |
| 重叠判据 | `D_m ∩ R_m ≠ ∅  ⟺  d_lo ≤ r_hi`（**必要**条件） |
| 充分形式 | 同一 pass 的某次执行消费了它自己更早一次执行的输出，即 `in_b ∈ R_a, a<b` |
| 复合次数 | `y = f^n(x)`；Reinhard 有闭式 `f^n(x)=x/(1+nx)`，故 `n=(x-y)/(xy)` |
| 通过条件 | `\|y − f(x)\| ≤ q`，`q=1/1023` 为 10-bit present 的一个量化级 |

只有 Reinhard 一个 pass 真正改值；dof/present 是恒等映射，重复它们挪不动
像素，亮度判据在结构上看不见——只有该档记了 pass 行才能点名。

## 三档（每次运行实测，非假定）

| 档 | pass 行 | 行数 | 检测 | 点名 |
|---|---|---|---|---|
| lo | present | 1 | 是（亮度反解 n=2） | 无区间 |
| mid | T/B/O | 3–4 | 是 | T，带实测区间 |
| hi | 全部 | 4–6 | 是 | T + D，带实测区间 |

事故运行时日志大小：lo 122 B / mid 311 B / hi 437 B。

## 方案取舍

- 标记位：6 pass × 1 bit = 0.75 B/帧，**防重复**，但维护 6 个 reset 点；
  它记不住是哪个步骤触发的。
- 只靠日志：事后才发现，坏帧已经出了；按档 122/311/437 B/帧。
- 交叉点：重复率 r < 0.9% 时日志更准；r ≥ 0.9% 标记位更准，且任何 r 下都更省。
  d=0.15%/reset 点是唯一假定值，其余数字均从日志文件实测。

结论：默认上标记位（防）；lo 档日志留作归属通道（亮度反解次数，所有档都行）；
调查时临时开到 hi。
