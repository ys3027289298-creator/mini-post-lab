# detcheck

确定性检验 harness：对同一输入把后处理插件跑两遍（外加多轮重复），逐像素比较，
定位「同输入两次运行输出差在最后一个量化级」的来源。`src/plugin.c` 是可开关
三类缺陷的模拟第三方插件，`src/harness.c` 负责扫描分辨率 × 线程数 × 缺陷模式。

## 判据表达式

设管线输出 `O = F(I, π)`：`I` 为全部输入（像素、参数、种子、分辨率），
`π` 为全部非结合浮点运算的归约顺序（线程划分、部分和合并顺序、缓存命中路径）。
浮点加法只交换不结合，`(a+b)+c ≠ a+(b+c)`，故 `∂F/∂π ≠ 0`：

    O 唯一  ⟺  (I₁ = I₂)  ∧  (π₁ = π₂)

量化 `q = ⌊v·255 + 0.5⌋`：ulp 级 `|Δv|` 仅当 `v·255` 落在舍入边界 `±|Δq|` 内才翻转，
所以差异表现为最后一个量化级 ±1 —— 这正是观测到的症状。

## 三个破坏 π 的来源及各自触发条件

1. **插件内部多线程归约（到达序合并）**：部分和按线程完成先后并入共享累加器。
   产生差异的条件：线程数 > 1 ∧ 合并顺序取决于运行时调度 ∧ 累加器为有限精度浮点。
   注意线程数本身也是 π 的一部分：同一固定顺序归约，T=2 与 T=8 结果可以不同但都确定。
2. **浮点累加顺序**：即使单线程，两次运行的加法括号化不同也会差在末位。
   产生差异的条件：累加链长到舍入不可忽略（float32 下 n≈1e6 时顺序噪声 ~1e-7 相对量级）
   ∧ 两次运行走了不同括号化（分块划分、SIMD 宽度、缓存 hit/miss 路径）。
3. **插件自维护缓存**：第一次 miss 算、第二次 hit 取，两条路径各走一次。
   产生差异的条件：命中路径与未命中路径不位等（如缓存经 `%.6f` 文本序列化往返）
   ∨ 缓存键未包含全部影响输出的状态（线程数、模式）∨ 写入侧本身不确定且两次运行间未失效。

## 反解残留不确定性

设单像素翻转概率为 `p`，两次运行差异像素数 `D` 服从二项分布，`p̂ = D/N`。
`D = 0` 时 95% 置信上界 `p < 3/N`（rule of three），N 为总比较像素数。
**通过判据只有 `D = 0`**；`D = 0` 在小 N 下不等于确定，只是残留不确定性被压到 `3/N` 以下。
本仓库 shipped 配置（fixed-order + 每次运行清缓存）实测 `D = 0`，
`N = 193,536,000` → `p < 1.55e-8`。

## 取舍与线程策略

实测 1920×1080（本机 16 核）：耗时 T(t) ≈ 7.9 / 4.3 / 2.8 / 2.8 ms（T = 1/2/4/8，
T=4 后进入平台期）；racy 与 fixed-order 的 T(t) 曲线在噪声内重合，
而 D(t) 只有 racy 在 T>1 时非零。结论：**固定合并顺序后确定性与多线程不冲突**，
取 T(t) 曲线拐点（本机 T=4）即可，无需为确定性退回单线程。
仅当插件闭源、只能整体强制单线程时，才退而求其次：归约阶段 T=1、
map 阶段（逐像素无共享状态，任意并行都确定）T=max。

## 测试输入的一个陷阱

输入若来自粗量化网格（如 `rand()%1000`），q 值只落在格点上，可能全部远离
舍入边界，把末位翻转完全掩盖（本 harness 第一版因此全绿）。测试输入必须是
有效连续的 float32 分布。

## 运行

```
make test
```

输出每行：分辨率、线程数、归约模式、缓存模式、`diff12`（第 1、2 次运行的差异
像素数，通过判据）、`diffAll`（全部重复轮累计）、首个差异像素的坐标与两边的值、
当前线程数、平均耗时。
