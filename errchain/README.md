# errchain — 后处理串联误差累积实验

复现并量化「雨天单看每步都干净、串起来就脏」的问题。纯 C、零第三方依赖，
与 `tonemap/`、`bloom/`、`dof/` 同构（`make test` 自测，产物落在 `artifacts/`）。

## 1. 串联误差表达式

设管线有 N 个处理步骤，第 i 步在存储中间结果时引入本地误差 eᵢ（相对误差
δᵢ = (qᵢ−vᵢ)/vᵢ，分母取 `max(|vᵢ|, 1e-3)` 防除零）。各步把误差经算子增益
gⱼ（tonemap 斜率、模糊核权重、钳位等）传到输出，记为 Eᵢ。总输出误差

- **误差同向（同号，线性叠加）**：各 Eᵢ 朝同一方向，幅值相加
  E = |Σᵢ Eᵢ| ≈ Σᵢ |Eᵢ|，最坏情形，误差随步数 N **线性增长**。
- **误差反向（异号，部分抵消）**：符号混合、近似独立，按平方和开根
  E = √(Σᵢ Eᵢ²)，随步数 **√N 增长**，抵消越多增长越慢。

实验里用两个量把这两种情形钉死：

- **模型核对**：同时打印线性和 `Σ|Eᵢ|` 与 RSS `√ΣEᵢ²`，看实测 E 更靠近哪条。
  R8 失败链实测/线性 ≈ 1.0（被一项主导偏置锁定，接近线性）；
  浮点链实测/RSS ≈ 1.45、且 `|signed mean|/RMS → 0`（真抵消）。
- **相干性** `coherence = |signed mean| / RMS`：→1 表示误差齐指一个方向
  （同向），→0 表示互相抵消（反向）。

## 2. 同向还是反向 —— 符号判据

**判据（按用户给定形式）**：统计误差符号，若同号占多数（这里取 ≥60% 阈值）
即判为同向。实验给了两层统计，并指出朴素做法的陷阱：

- **输出端像素符号（主判据）**：对端到端逐像素误差 d = test−ref 数正/负/零。
  这是幅度感知的——主导的偏置步骤会把大多数像素的符号翻到同一侧。
- **逐存储点本地符号（辅助）**：把每步本地舍入的正负零直接加总。

> 关键陷阱：纯本地符号计数在本实验全部读成约 50/50（混合），但 R8 输出端
> 98.6%~100% 的非零像素都是负误差。原因是大量**零均值小舍入噪声**把主导步骤的
> **系统性钳位偏置**在计数上稀释了。因此最终判据采用输出端符号，本地符号仅作诊断。
> 另加门槛：非零像素占比 <5% 时判为「sub-quantum，可忽略」，避免薄样本误判。

实测结论：

| 场景 / 精度 | 非零像素占比 | 负号占比 | 相干性 | 判定 |
|---|---|---|---|---|
| light / R8 | 0.632 | 0.986 | 0.53 | **同向·净负·线性** |
| medium / R8 | 0.975 | 0.999 | 0.79 | **同向·净负·线性** |
| heavy / R8 | 0.998 | 1.000 | 0.90 | **同向·净负·线性** |
| 任意 / R16F | ≤0.042 | — | ≤0.04 | 亚量化级，可忽略（抵消） |
| 任意 / fp32 | 0 | — | 0 | 无可见误差 |

即：**脏链是同向的，且方向为负**（压暗 + 去饱和）。根因是 R8 中间缓冲无法承载
HDR——第一个 R8 存储点把 >1 的高亮硬钳到 1.0，这是带固定方向的偏置，无法靠后续
零均值舍入抵消。雨越大、HDR 峰值越高（2.4→12.6→18.7），被钳的像素越多，同向性越强。

## 3. 反解每步误差上限（预算 Q = 一个量化级）

要求端到端总误差不超过一个 8-bit 量化级 Q = 1 LSB。名义链 N=11：

- 同向（线性）：`Σ eᵢ ≤ Q` ⇒ 等权下每步 **eᵢ ≤ Q/N = 0.0909 LSB**
- 反向（RSS）：`√(Σ eᵢ²) ≤ Q` ⇒ 每步 **eᵢ ≤ Q/√N = 0.3015 LSB**

步骤越多，每步预算越紧（线性按 1/N、RSS 按 1/√N 收紧）。报告对每条链打印
主导步骤实测贡献与 `Q/N` 的核对：R8 主导步（exposure）实测 9~98 LSB，
超上限 100~1080 倍，**OVER CAP**；R16F/fp32 各步均在 0.30 LSB 内，达标。

## 4. 用两条曲线定步骤数 N

固定 `kb=kd=k`，链长 N = 5 + 2k，扫描 k=1..5（N=7..15），每个 N 画两条曲线：

- **总误差曲线** E(N)：受预算线 Q=1 LSB 约束，先求可行域（曲线在预算线下方的 N）。
- **画质曲线** q(N)：bloom 响应相对理想宽核（r=6）模糊的接近度，0~100。

**取舍**：步骤少误差好控但 bloom 弱（画质低）；步骤多画质高但误差预算更紧。
拐点 N* 取「可行域内，画质达到平台 90%、或再增 2 步的边际增益 <1 分/步」的最小 N
（`pick_knee`）。实测：

- R8：三场景**无可行 N**（整条扫描都在预算线上方，误差 8~104 LSB），无法靠减步救活。
- R16F：全程可行，拐点 N*=9~11（画质 86%+，误差仍 <0.21 LSB）。
- fp32：全程可行，误差恒 0，拐点同样 N*=9~11（由画质曲线决定）。

### 超预算案例的完整交代（三场景 R8 均超）

以最重的 **heavy_rain / R8**（N=11，实测 98.21 LSB，超预算 ~98 倍）为例：

- **步骤数**：N=11（exposure, bright_pass, bloom_blur×3, aces, dof_blur×3, composite, sdr_q8）。
- **各步误差符号分布（本地正负零计数）**：见 `step_metrics.csv` 与分解 SVG。
  exposure 负 1406 / 正 898（净负）；bright_pass 在全链里因输入已被钳位而本地误差极小，
  但单步消融（面对未钳位 HDR）达 −53.3 LSB，与 exposure 同属第一个 R8 钳位点。
- **贡献最大的一步**：**exposure，消融 98.21 LSB，方向净负**——它是全链第一个 R8 存储，
  把 HDR 高亮（峰值 18.7）硬钳到 [0,1]，单一偏置步骤即解释几乎全部端到端误差。

### 工程结论

「脏」不是任何单步的算术错误，而是 **R8 量化在 HDR 管线上的系统性钳位偏置沿链同向
（负）累积**。修复方向（按性价比）：

1. 中间缓冲改用 **R16F（半精度浮点）**：保留 HDR 范围，三场景全部达标（<0.21 LSB），
   是本实验支持的最小改动；fp32 余量最大但收益已不可见。
2. 钳位推迟到最终 SDR 编码（`sdr_q8`），让 tonemap 之前的所有中间结果保持浮点/HDR。
3. 必须用 R8 时，在第一个存储点前做 HDR→LDR 的 tonemap，而非线性硬钳，并对该步单独加预算。

## 复现性

- 确定性 RNG（LCG），无随机种子；`-O0` 与 `-O2` 产物 CSV 逐字节相同，重复运行稳定。
- 参考链全程 double、不量化；测试链用同一套算子，仅在中间存储点插入量化器，
  保证差异只来自量化，不来自算子实现分歧。
- 三档量化器：`R8_UNORM`（256 级 + [0,1] 硬钳）、`R16F`（10 位尾数半精度）、
  `fp32`（23 位尾数）。
