# gamma

判断 `sRGB ≈ x^(1/2.2)` 这条补偿在什么范围内成立。`make test` 跑自检并打印推导量与三档实测。

## 结论摘要

- 纯幂误差的闭式峰值：`x* = (12.92·2.2)^(-2.2/1.2) ≈ 0.0021623`，`Δ* ≈ 0.03352`，即 **8.55 个 8 位量化级**，且落在暗部（输出码值 7.1 附近）。
- 「暗部偏差 ≤ 1 个量化级」要求目标位深 `L` 满足 `Δ*·L ≤ 1`，即 `L ≤ 29.8`，等价于 **位深 ≤ 4.9 bit**。8 bit 下纯幂在暗部必然超标，与实现无关。
- 8 bit 下纯幂仅在三段码值区间内合规：`[0, 0.02]`、`[80.0, 129.1]`、`[218.5, 255]`。
- 分段函数的接点有容差窗口：8 bit 时为 `x ∈ [0.00153, 0.00510]`（码值 5.05–15.80），规范的 `K = 0.0031308`（码值 10.3）居中，余量最大。
- 三档实测暗部最大偏差：夜景 8.55、室内 5.72、日光 0.73 个量化级。前两档超标，日光档暗部达标但整档仍在中调差 1.46 级。

## 推导

线性值 `x`，参考编码 `E(x)`，补偿 `P(x) = x^(1/2.2)`，偏差 `D(x) = P(x) − E(x)`。

暗部 `x ≤ K` 时 `E(x) = 12.92x`，故

```
D(x) = x^(1/2.2) − 12.92x
D'(x) = (1/2.2)·x^(1/2.2−1) − 12.92 = 0
x* = (12.92·2.2)^(−2.2/1.2)
Δ* = D(x*) = 12.92·x*·(2.2−1)
```

`Δ*` 是全局峰值（比中调负向凹陷 `−0.00584`，约 1.49 级，更大），所以「暗部偏差」就是全局最坏情况。

## 输出字段

`gamma` 程序：

| 字段 | 含义 |
|---|---|
| `x_star` / `delta_max` | 峰位与峰值（线性值） |
| `delta_max_8bit_lsb` | 峰值折成 8 位量化级 |
| `bits_pure22_ok` | 纯幂误差 ≤ 1 级所允许的位深上限 |
| `safe8_*` | 8 位下纯幂合规的码值区间 |
| `knee_window_bits_*` | 各目标位深下接点可落范围 |
| `tier,...` | 三档亮度的暗部/整档最大偏差，及两种替代实现 |

`bench` 程序：按三档分布与「暗部占比扫描」两种方式，测每种实现每像素耗时（ns/px，单线程，最小值）。时间随机器与负载变化，不作断言，只作参考。

## 取舍

- **纯幂**：0 分支，暗部最多偏 8.55 级（8 bit），只在低动态范围或 ≥10 bit 高位深的中间产物上可接受。
- **分段**：精度到浮点级别，代价是数学上的一次比较。但可测的额外开销不是「一次比较」这么小：接点被随机跨越时，分支预测失败会把每像素从约 2.4 ns 拉到 4–5 ns（本机负载下的量级），而整帧落在接点同侧时几乎无差。夜景档恰好是薄薄一片跨在接点两侧的分布，是最坏情形。
- **无分支偏移幂**（`max(1.055·x^(1/2.4)−0.055, 0)`）：没有不可预测分支，代价固定，但暗部会被钳到 0，最大偏 2.75 级，只适合暗部本来就被压到黑的处理。
- **查表**：2048 项最近邻，最大 0.80 级，每像素开销最低且与暗部占比无关；要压到 0.1 级以内需要 4096 项加线性插值或分位深建表。

## 建议

1. 遗留代码里的 `×2.2` 若作用在最终 8 位输出上，**不能保留**：暗部 8.55 级是可见的暗部塌陷，不是舍入噪声。
2. 若只是中间过程的亮度线性化/反线性化，先确认中间缓冲位深；≥5 bit 精确表示、且暗部不进最终量化时，纯幂可继续用，但要把「亮度范围」写进注释而不是「补偿伽马」。
3. 必须上 8 位输出的路径：优先查表（精度和成本都最好）；其次分段，接点取规范 `K`，并在帧级决定是否需要为夜景单独走一条不跨接点的路径。
4. 无论哪种，注释里应写清适用位深与亮度范围，替换掉「别删」。
