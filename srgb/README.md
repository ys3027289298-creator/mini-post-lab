# srgb

核对「贴图按 sRGB 存储、后处理缓冲为线性」这条规格。`make test` 会实际跑
10 / 100 / 1000 三档资产数量并自检；`make bench` 测解码开销。

## 结论先放

- 直接把 sRGB 码值 \(c\) 当线性值，误差峰值为
  \(\Delta_{\max}=0.2871359\)（归一化线性光），等于 **73.22 个 8-bit 量化级**。
- 连续峰值出现在 \(c_*=0.5315188\)，即 **sRGB code 135.54、整数码 136**；
  该码值正确解码后的线性亮度为 \(L_*=0.2443828\)（约 24.4% 线性灰）。
- 若把「错用比例」定义为等权混合/批次平均中的未解码保守占比，
  \(\alpha_{\max}=q/\Delta_{\max}=1.3658\%\)。
- 若「最大偏差」是逐资产最大值而不是混合误差，则这个比例不能用来放过任意
  全色域资产：**只要有 1 个未解码的全色域资产，最大偏差仍是 73.22 级**。
  严格最大偏差达标方案是全部解码，或只允许码值集合为 `{0,1,255}` 的资产跳过。
- 推荐：颜色贴图全部走硬件 sRGB 格式/采样器解码；没有硬件格式时用 256 项
  LUT。省掉解码幂函数只能省约 1.37% 的调用量，却会留下 73 级错误，不划算。

## 1. 存储空间与计算空间

设 \(c\in[0,1]\) 是 sRGB 存储值，\(l\in[0,1]\) 是线性计算值。IEC
61966-2-1 的分段 EOTF（存储 → 线性）为

\[
l=D(c)=
\begin{cases}
c/12.92, & 0\le c\le 0.04045,\\[2mm]
\left(\dfrac{c+0.055}{1.055}\right)^{2.4}, & 0.04045<c\le1.
\end{cases}
\]

反向 OETF（线性 → 存储）为

\[
c=E(l)=
\begin{cases}
12.92\,l, & 0\le l\le0.0031308,\\[2mm]
1.055\,l^{1/2.4}-0.055, & 0.0031308<l\le1.
\end{cases}
\]

这里的「开方」严格说是开 \(2.4\) 次方，即指数 \(1/2.4=5/12\)，不是平方根。
若项目实际使用 gamma-2 简化模型 \(l=c^2,\ c=\sqrt l\)，对应结果见文末对照。

## 2. 不对齐的最大偏差

不解码时，着色器拿到的错误线性值是 \(\tilde l=c\)，故

\[
\Delta(c)=\tilde l-l=c-D(c).
\]

在线性段 \(\Delta(c)=c(1-1/12.92)\)，峰值只有约 \(0.0373\)。全局峰值在幂
分支。令 \(L=D(c)\)，则

\[
\Delta'(c)
=1-\frac{2.4}{1.055}
\left(\frac{c+0.055}{1.055}\right)^{1.4}
=1-\frac{2.4}{1.055}L^{7/12}.
\]

令导数为零：

\[
L_*=\left(\frac{1.055}{2.4}\right)^{12/7}=0.2443828129,
\]

\[
c_*=1.055L_*^{5/12}-0.055=0.5315187509,
\]

\[
\boxed{\Delta_{\max}=c_*-L_*=0.2871359380.}
\]

8-bit 全范围归一化用 \(q=1/255\)，所以

\[
\boxed{\Delta_{\max}/q=255\Delta_{\max}=73.2197\text{ 级}.}
\]

逐整数码扫描的最坏码是 **136**（\(c=136/255=0.5333333\)，正确线性值
\(0.2462013\)），离散峰值为 \(73.2187\) 级。

### 「暗部抬亮、亮部压暗」要精确表述

- 暗部：接点以下 \(l=c/12.92\)。同一个 \(c\) 被直接当线性值时，数值是正确
  线性值的 \(12.92\) 倍，暗部/中间调明显发灰、抬亮。
- 高光：原始 \(\Delta(c)=c-D(c)\) 在 \([0,1]\) 上非负，所以**在 tonemap 前
  的绝对数值并没有变低**；不准确的说法是「高光绝对值被压暗」。真实发生的
  是高光层次被压缩：白点处 \(D'(1)=2.4/1.055\approx2.275\)，而错用恒等曲
  线的斜率只有 \(1\)，局部高光反差只剩 \(1/2.275\approx44\%\)。错误抬高的
  亮度进入 Reinhard/ACES 肩部或触发自动曝光后，高光余量和层次会被压掉，
  观感上常被描述为「亮部发闷/压暗」。

## 3. 「不超过一个量化级」反解比例

以 8-bit 贴图为例，一个量化级 \(q=1/255=0.00392157\)。

### 3.1 保守混合/批次平均比例

设 \(\alpha=k/N\) 是未解码资产的等权占比，并且这些资产都恰好包含最坏亮
度，则最保守的聚合偏差为

\[
\Delta_{\text{agg}}^{\rm wc}(\alpha)=\alpha\Delta_{\max}.
\]

要求 \(\Delta_{\text{agg}}^{\rm wc}\le q\)：

\[
\boxed{
\alpha_{\max}=\frac{q}{\Delta_{\max}}
=\frac{1}{255(0.287135938)}
=0.0136575\approx1.366\%.
}
\]

通用 \(B\) 位全范围量化为

\[
\alpha_{\max}(B)=\frac{1}{(2^B-1)\Delta_{\max}}.
\]

例如 10-bit 线性输出/呈现缓冲下收紧到 \(0.3404\%\)，16-bit 下为
\(0.00531\%\)。如果用 256 个 bin、步长 \(1/256\) 而不是 full-range 的
\(1/255\)，8-bit 结果为 \(1.360\%\)，取整结论不变。

### 3.2 严格逐资产最大偏差

最大偏差不会因为只有 \(1\%\) 资产未解码而自动乘上 \(1\%\)。如果管线对每个
资产独立采样、过滤和 tonemap，那么任意一个未解码的全色域资产都能达到
\(73.22q\)。因此在这个口径下：

\[
\boxed{k_{\max}=0\text{ 个任意全色域资产}.}
\]

只有整个色调范围都落在安全区间内的资产可以跳过。解
\(\Delta(c)\le1/255\) 得连续区间

\[
c\in[0,\ 0.0042506]\ \cup\ [0.9969127,\ 1],
\]

总宽度只占归一化存储范围的 \(0.7338\%\)。落到整数 8-bit 码值，安全集合恰为

\[
\boxed{\{0,1,255\}.}
\]

也就是说，只有纯黑、纯白和 code 1 的极小范围色卡能在逐资产最大误差口径下
不解码；真实贴图通常包含 code 10–245，不满足这个条件。

## 4. 三档资产数量实跑

题目没有给出具体资产清单或三档数量，下面取自然的小/中/大三档
**\(N=10,100,1000\)**；程序中的公式可直接换成实际 \(N\)。

### 4.1 聚合误差预算内的最大可不解码数量

\(k_{\text{agg}}=\lfloor N\alpha_{\max}\rfloor\)：

| 档 | \(N\) | 预算内 \(k\) | 未解码占比 | 保守聚合最大误差 | 严格逐资产最大误差 |
|---|---:|---:|---:|---:|---:|
| small | 10 | 0 | 0% | 0 级 | 0 级（无未解码资产） |
| medium | 100 | 1 | 1.0% | 0.732 级 | **73.219 级** |
| large | 1000 | 13 | 1.3% | 0.952 级 | **73.219 级** |

所以 100 和 1000 档的 \(1/100\)、\(13/1000\) 只通过「聚合/平均」口径，不通
过逐资产最大偏差口径。要让题目所说的**最大偏差**达标，工程方案仍是全部解
码；本模块自检同时锁定这一区别。

### 4.2 第一个整数上超的档位（`make test` 实测）

| 档 | 上超 \(k\) | 未解码占比 | 聚合偏差最大值 | 逐资产偏差最大值 | 出现亮度 |
|---|---:|---:|---:|---:|---|
| small / 10 | 1 | **10.0%** | **7.322 级** | **73.219 级** | code 136，\(c=0.5333\)，\(l=0.2462\) |
| medium / 100 | 2 | **2.0%** | **1.464 级** | **73.219 级** | 同上 |
| large / 1000 | 14 | **1.4%** | **1.025 级** | **73.219 级** | 同上 |

完全不解码的基线在三档中都是未解码占比 **100%**，最大偏差 **73.219 级**，
位置同样是 code 136。

## 5. 颜色准确度与采样开销曲线

令 \(\alpha\) 为跳过解码的等权样本/资产比例：

\[
E_q(\alpha)=73.2197\,\alpha\quad\text{（量化级）},
\qquad
C_{\rm pow}(\alpha)=1-\alpha
\quad\text{（相对 pow 调用量）}.
\]

| 跳过比例 \(\alpha\) | 最大误差 | 相对 pow 开销 |
|---:|---:|---:|
| 0%（全部解码） | 0 级 | 100% |
| 1.366%（聚合边界） | 1.000 级 | 98.634% |
| 1% | 0.732 级 | 99.000% |
| 2% | 1.464 级 | 98.000% |
| 10% | 7.322 级 | 90.000% |
| 50% | 36.609 级 | 50.000% |
| 100%（不解码） | 73.219 级 | 0% |

两条曲线的约束交点只允许省掉 \(1.37\%\) 的 pow 调用；对 10 个资产取整后甚
至是 0 个。为这么小的开销收益接受 73 级颜色错误不成立，因此方案是：

1. **默认全部正确解码**：贴图使用 sRGB image format / sampler，让硬件在过
   滤前后按管线约定完成 EOTF；着色器不手写 `pow`。
2. 若目标 API 没有 sRGB 采样格式，使用 **256 项 float/half LUT**：初始化
   时计算一次，采样时一次查表，避免每样本幂函数。
3. 只对规格明确保证为 `{0,1,255}` 或连续安全区间内的特殊资产跳过；普通
   albedo/color map 不进入白名单。normal/roughness 等数据贴图是否应标为
   sRGB 是另一个规格问题，不能用本结论把数据贴图也改成颜色解码。

本机 WSL 一次微基准（`make bench`，数值随机器/负载变化，不作断言）：

```text
identity / no-decode : 1.06 ns/sample
piecewise pow decode : 15.41 ns/sample   (约 14.6× identity)
256-entry LUT        : 0.48 ns/sample
```

## gamma-2 简化模型对照

若规格实际写的是近似关系 \(l=c^2\)、反向 \(c=\sqrt l\)，则

\[
\Delta(c)=c-c^2,\qquad
\Delta'=1-2c=0\Rightarrow c_*=\frac12,
\qquad
\Delta_{\max}=\frac14.
\]

对应 8-bit 峰值为 \(63.75\) 级，聚合比例边界

\[
\alpha_{\max}=\frac{1/255}{1/4}=\frac4{255}=1.569\%.
\]

这与精确 sRGB 的 73.22 级、1.366% 不同；验收规格既已写明 sRGB，应以分段
IEC 曲线为准。另一个常见问题「纯 gamma 2.2 近似与分段 sRGB 的暗部差别」峰
值约 8.55 级，也不同于本题把 sRGB 码值直接当线性值的 73.22 级。

```sh
cd srgb
make test     # 推导量、256 码扫描、三档数量、取整边界和自检

```
