# bench

后处理管线「可跳过性」基准台与策略分析。复用 `tonemap/`、`bloom/`、`dof/`
三个模块里的同一套数学（ACES 曲线、bright-pass + 可分离盒式模糊、薄透镜
CoC + 钳制半径），在确定性 HDR 测试场景上测量每级耗时与跳过后的画面差异。

## 构建与运行

```sh
make run       # 编译并跑基准，输出 bench_out.txt（CSV 行）
make analyze   # 再跑 python3 -I analyze.py，生成 summary.json 与 tradeoff.html
```

建议 `taskset -c 0` 绑核（Makefile 的 run 目标已自动尝试），耗时取 31 帧中位数。

## 判据

后处理步骤集合 S 可跳过，当且仅当跳过 S 后与全量参考帧的显示空间差异
低于可察觉阈值：

```
Skippable(S)  ⇔  D(I_full, I_{full\S}) ≤ ε
```

实测取 D = 显示空间（[0,1] LDR）逐通道 RMSE，阈值 ε = 0.0200（≈ 34 dB PSNR）。
同时输出 MAD、最大像素差与受影响像素占比作旁证。

## 三档负载（L2 全量标定到题目给定的 5.2 ms）

| 档位 | 分辨率 | 全量耗时 |
|---|---|---|
| L1 | 384×216 | ~2.4 ms（本来就在 3 ms 预算内） |
| L2 | 552×311 | ~5.13 ms（锚定 5.2 ms） |
| L3 | 640×360 | ~7.0 ms |

## 结论（数字随机器有波动，以本地实跑为准）

- 色调映射不可跳：RMSE ≈ 0.108，96.8% 像素受影响（全画面变暗）。
- 泛光可跳：RMSE ≈ 0.0029，仅 ~1.4% 像素受影响（高光附近）。
- 景深可跳：RMSE ≈ 0.0096，~35% 像素受影响但幅度小（仅焦外）。
- 反解：阈值内最大可跳过数量 = 2（泛光+景深同时跳，RMSE ≈ 0.0098 仍 < 0.02）。
- 预算策略（两条曲线交点：满足 3 ms 的最小跳过数）：
  - L1：不跳，2.41 ms；
  - L2：跳景深（省 ~2.86 ms）→ 2.27 ms；只跳泛光仍 3.25 ms 超预算；
  - L3：先跳景深（省 ~3.85 ms，余 3.16 ms 仍超）再跳泛光（再省 ~2.65 ms）→ 0.52 ms。

`tradeoff.html` 含两条曲线（省时间–差异曲线、各方案剩余耗时+预算线）、
明细表与悬浮提示，支持深浅色。
